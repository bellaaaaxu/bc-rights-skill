# 裁决集（decision benchmark）

用 BC 就业标准仲裁庭（Employment Standards Tribunal，BCEST）的公开裁决当测试案例：没有隐私问题，裁决本身就是标准答案。它只测「模型有没有正确复述裁决里已定的规则和事实」，不测早期案件的正确行动（见 `../rubric.md`）。

## 选案规则

- 来源：https://www.bcest.bc.ca/decisions/ 按年份列出的裁决（2022 到 2026），读裁决 PDF 全文。
- 要：员工向 ESB 投诉欠薪类（工资、加班、法定假日、年假工资、辞退补偿、扣款、提成或池子）且裁决里事实写得清楚、能看出员工当时知道什么的案子。
- 分层：辞退补偿 2、加班 2、员工身份争议 1、扣款 1、提成或池子 1，另 1 个备选。
- 不用已经试过的两例：2022 BCEST 37、2023 BCEST 103。
- 人名、店名一律化名。

## 每例一个文件夹 `<year>-BCEST-<n>/`

| 文件 | 给谁看 | 内容 |
|---|---|---|
| `narrative.md` | 帮手（被测的 skill）和扮演者 | 当事人第一人称的口语开场叙述，只说他当时知道的、会说的，不含法律术语、不含裁决结论；文首写「今天」设定为哪一天（事情刚发生不久） |
| `facts.md` | 只给扮演者 | 事实卡：当事人知道的事（分「确定」「不确定」）、不知道的事、扮演须知（问到什么才说什么，卡里没有的说不知道，不懂法律） |
| `answer-key.md` | 只给打分者，帮手写完材料包并记哈希之后才开 | 裁决号、链接、争议类型、裁决认定的关键事实、适用的条文、老板的说法、金额和算法、理想的帮手应该问到和找到的 |
| `hashes.txt` | 冻结证据 | 三个文件的 SHA-256 |

## 四个角色（沿 canada-law 的公开裁决试用协议）

| 角色 | 由谁担任 | 能看到什么 |
|---|---|---|
| 找案例的助手 | Claude 子代理 | 读裁决全文；写三个文件；向主会话汇报时不透露案情 |
| 扮演当事人 | Claude（`claude -p`，无 skill） | 只看 facts.md 和 narrative.md；只答问到的 |
| 帮手 | 装了 skill 的 Claude（`claude -p`，同一会话续接） | 只看 narrative.md 和问答；法条用 canada-law 取 |
| 打分 | Codex（跑不了就她手动贴给 ChatGPT） | 材料包写完、记哈希之后，才对照 answer-key.md |

主会话在跑分前不打开 `facts.md` 和 `answer-key.md`。

## 已知局限（照 canada-law 那次的自评）

四个角色可能是同一家模型；事实卡可能夹带提示；扮演者受问法影响；测不到「把全部记录抄成表」这一步；模型可能在训练中见过裁决；样本很小。
