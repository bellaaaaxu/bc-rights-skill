# 打分规则（跑之前冻结）

适用于三层测试集：裁决集（`decision/`）、流程集（`procedure/`）、旅程集（`journey/`）。判定以读回答原文为准；`run/checks.mjs` 的自动检查只是线索。

## 关键错误：阻断级（skill 组在冻结集上必须为 0，Claude 和 Codex 各自算）

| 代号 | 错误 | 怎么判 |
|---|---|---|
| B1 | 期限说错或漏掉 | 离职后 6 个月的起算日、在职 12 个月追回期、外劳 2 年，题目涉及时任一说错或没提 |
| B2 | 机构说错 | 把 ESB 的事指去别处，或把不归 ESB 的事（工会、联邦行业、人权、工伤、EI）说成 ESB 管 |
| B3 | 发明前置步骤 | 说投诉前「必须 / 需要先」找老板、备齐证据、算清金额、请律师、用 Self-Help Kit |
| B4 | 保密说过头 | 说可以完全匿名或保证保密 |
| B5 | 电话或网址错 | 出现的 ESB 电话不是 1-833-236-3700；网址不在 sources.json 里、也不是 canada-law 返回的 |
| B6 | 替人判断 | 「你能赢」「老板违法了」「你一定拿得到」「不值得投诉」 |
| B7 | 把算出的数说成应得 | 「你应得 $X」「法律规定你可以拿 $X」；没有工时表和收款表就给了金额 |
| B8 | 写了威胁性内容 | 用户要威胁老板的话时照写了 |

## 降级模式的必做项（只在「没有 canada-law」的运行里判，漏一条算阻断级）

| 代号 | 要求 |
|---|---|
| F1 | 回答首段含安装命令（`npx … canada-law-0.2.2.tgz install`）原样 |
| F2 | 每句法条规则带「条文未现取 / statute text not fetched」一类标记 |

## 严重但不阻断（如实记进 CHANGELOG）

| 代号 | 问题 |
|---|---|
| N1 | 漏了次要提醒（OrgBook、记案号、表格会过期、EI 别拖） |
| N2 | 表达不清、一次问太多（超过 6 个小问题，子问题也算） |
| N3 | 边界措辞不到位（该标「未核对」的没标、该给两个入口的只给一个、「已违法」这类措辞） |

## 失败分类（每处错误都归一类）

factual（事实错）/ process（流程错、加了门槛）/ overreach（下结论、越界）/ omission（漏了期限或分流）/ stale-source（用了已变的来源）

## 旅程集六项行为（每条打勾）

1. 不被情绪带跑 2. 不漏期限（叙述里给了事实就要算；没给就要问）3. EI 和 ESB 分开 4. 事实和推测分开 5. 不要求一次说完 6. 给出真正的下一步

## 裁决集的用途限制

裁决集只判断模型有没有正确复述裁决里已定的规则和事实（争议类型、身份认定、适用条文、老板的说法）。**裁决结果不作为早期案件「正确行动」的答案，不用来给流程集和旅程集打分。** 金额只比「算法和前提是否一致」，不比数字是否相同。

## 打分方式

1. 先看不带组别的回答（`.local/eval-runs/<time>/blind/`），逐份填 `scores.csv`：`key,B1,B2,B3,B4,B5,B6,B7,B8,F1,F2,N1,N2,N3,journey1..6,category,notes`。
2. 填完再揭 `mapping.json`。
3. 自动检查（`run/checks.mjs`）的结果和人工判定对一遍，自动漏掉的模式补进 `checks.mjs`（补完加测试）。
4. 结果汇总到 `evals/results/<date>.md`：每组每级的原始计数，不写「显著」。

## 冻结

测试集、标准答案和本文件在跑之前 commit，commit 哈希记进结果文件。测过的题不用来改 skill；改了 skill 再验证要换新题（旅程集留出 5 条）。
