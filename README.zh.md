# bc-rights-skill

[English](README.md)

把 BC 省的一个官方办事流程做成 AI 助手能稳定陪着走的指南：找谁、期限、第一步、不用先做的事、表格怎么理解、事实怎么整理。依据是当前的官方来源。

**现在只有一件事：`bc-unpaid-wages`（欠薪投诉）。** 它帮 BC 的打工人（或帮他的人）把欠工资、欠加班费、欠法定假日工资、欠年假工资的事拿到就业标准处（Employment Standards Branch，ESB）：找谁、截止日、第一步、**不需要先做**什么、官方投诉表怎么填、怎么把事实整理成 ESB 用得上的材料。中文或英文提问都行。

> **先看这几句**
> - 这是关于一个公共程序的一般信息，**不是法律意见**，也不替任何人判断案子。投诉由 ESB 裁定。
> - **回答默认简短**：先给期限、下一步、不用先做的事和最多 3 个问题。想看详细的，回复「详细」。
> - **不确定的会直说。** 查不到的日期、数字、网址不会编；官方来源最近变了的部分，会说「可能刚改过，请打 ESB 电话确认」。
> - 它拒绝三件事：预测你能不能赢、告诉你该接受多少钱、替你写威胁的话。没有工时表和收款表之前不给金额。
> - **没有证据表明使用它改善了真实投诉的结果。** 测过什么写在下面，而且是写它的人自己测的。

## 三种用法

**1. 任何聊天应用（最简单，不用装东西）**

下载贴文包，作为附件发给 ChatGPT、DeepSeek、Claude、豆包等，或整段贴进新对话，再写你的情况：

- 精简版（默认，约 8,400 token）：<https://github.com/bellaaaaxu/bc-rights-skill/raw/main/chat/bc-unpaid-wages-chat.txt>
- 完整版（要整理材料、看表格怎么填时用，约 16,800 token）：<https://github.com/bellaaaaxu/bc-rights-skill/raw/main/chat/bc-unpaid-wages-chat-full.txt>

这两个文件每周自动更新。聊天版取不到现行法条原文，规则来自每周自动核对过的参考资料，每次回答末尾会写明核对日期。

**2. claude.ai 或 Claude 桌面版**

在[发布页](https://github.com/bellaaaaxu/bc-rights-skill/releases)下载 `bc-unpaid-wages.zip` 和 `canada-employment-law.zip`，在 **Customize → Skills → + → Upload a skill** 里两个都传上去（需要在设置里开着「Code execution and file creation」）。2026-09-29 实测能触发。claude.ai 的沙箱可能连不上 BC Laws 官网，那时回答会说明取不到现行原文，按参考资料回答。

**3. Claude Code、Codex 等能跑脚本的助手**

需要 [Node.js](https://nodejs.org) 20 以上。先装 `canada-law`（取现行法条原文），再装本 skill：

```bash
npx https://github.com/bellaaaaxu/canada-law/releases/download/v0.2.3/canada-law-0.2.3.tgz install
```

```bash
npx skills add bellaaaaxu/bc-rights-skill
```

也可以手动把 `skills/bc-unpaid-wages` 复制到助手的 skills 目录，例如 `~/.claude/skills/`（Claude Code）或 `~/.agents/skills/`（Codex）。

## 自动维护，不需要人审核

- **每周一次**，GitHub 自动把全部 22 个官方来源重新核对一遍：ESB 页面上的关键句子还在不在、投诉表 PDF 有没有换、引用到的 41 条法条原文有没有改。
- **哪个来源变了，就只停用引用它的那部分。** 参考文件里每一句都标了来源；变了的那部分不再说，改成「这条的官方来源可能刚改过，请看官方页面或打 1-833-236-3700 确认」。法条按条停，一条改了不会让整部法都停。其他没变的照常回答。
- **装在本机的副本也会跟上**：能联网时，skill 每次先读 GitHub 上最新的核对结果，不用重新安装。这一步只向 GitHub 请求一个公开文件，不带任何个人信息。
- **兜底**：如果自动核对停了超过 180 天（比如 GitHub 任务停了，或者一份离线副本太旧），就不再陈述任何法律规则，只给官方链接和电话。180 天是这个项目自己定的阈值，不是法律规定。
- 第一次写参考文件时，是 AI 助手在会话里逐条读了官方页面和法条原文，不是律师核对。

## 测了什么，没测什么

完整的计数、方法和局限：[`evals/results/`](evals/results/)。下面全是小样本的原始计数，打分标准里有九种**阻断级**错误（期限说错、机构说错、发明前置步骤、保密说过头、电话或网址错、替人判断、把算出的数说成应得、写威胁内容、把没查到的日期或数字当成查到的说）。

| 测试 | 结果 |
|---|---|
| 短答版（v0.2），5 道新题 × 3 种用法 | 15 份里 0 份有阻断级错误 |
| 短答版回归，旧题 32 道 × skill 和聊天版 | 64 份里 0 份有阻断级错误；首答长度中位数从 500 到 770 字降到约 280（skill）和约 210（聊天版） |
| 聊天版贴文包，Claude 不给任何工具，40 题 | 贴了包 0 / 40 有阻断级错误；没贴包 23 / 40 |
| 聊天版贴文包，GPT 模型（经 Codex），10 题 | 0 / 10 |
| v0.1 冻结测试集（Claude Opus 5.5 装 skill） | 22 个固定情境 2 / 22；10 条乱叙述 0 / 10；8 份公开裁决 2 / 8（都是期限在「事发那年的规定」这一层） |
| 模拟官方来源改动 | 期限那一页和第 74 条被标成已改动后：聊天版不再说期限、改叫人去官网或打电话；装了法条工具的 skill 去官网取现行原文再说 |

**已知问题**：英文首答约一半超过 150 词的目标；第一个问题常把「还在上班吗、不在的话最后一天是哪天」塞在同一个编号里；在不开思考功能的测试环境里，少数回答开头会漏出模型自己的草稿笔记（修正后 8 次里 1 次）。

**没测的**：真实的 DeepSeek、豆包、ChatGPT 网页版；任何真实的打工人、任何真实投诉。打分者就是写这个 skill 的那个助手。

## 费用

- 装 skill：一份回答约 4 到 5 轮工具调用（以前 7 到 11 轮），Claude 约 0.15 美元。
- 聊天版：第一轮要读一遍贴文包（精简版约 8,400 token），之后同一对话的每一轮都会带着它。
- GPT 模型经 Codex 用精简版：一份约 3.3 万 token；装 skill 时是 15 万到 24 万。

## 一份回答是怎么来的

1. **一条命令启动。** `scripts/start.mjs` 一次输出状态（最新的自动核对结果）和第一轮要用的两份参考文件。
2. **只在需要时取法条。** 第一轮一般不用；被问到加班、假日这类规则或要看原文时，经 `canada-law` 从官网取。取不到就直说，不从别处补。
3. **参考文件**（中文）：分流与期限、第一步、提问清单、材料包模板、投诉表怎么理解、老板常见的说法、常见的坑。每句都标来源。
4. **十六条规则**在 `SKILL.md` 里，每条都是某次测试出错后加的：期限先写成条件式、不发明前置步骤、不下结论、默认短答、只说查到的等等。

## 报错

开一个 [GitHub issue](https://github.com/bellaaaaxu/bc-rights-skill/issues)，引出错的那句话，能的话附上与之矛盾的官方来源。**不要把你自己的案件材料、姓名、雇主名、工资记录贴进 issue。**

## 开发

```bash
npm test                         # 单元与结构测试
npm run validate                 # skills-ref validate
npm run check                    # 重新核对 22 个官方来源（法条部分要装 canada-law）
node scripts/build-chat-pack.mjs # 重新生成 chat/ 里的两个贴文包
```

`npm run accept` 是可选的：有人读过变动的来源、改好参考文件后，用它记下新的基准。不做也不影响安全，变了的部分会一直停着。跑分程序在 `evals/run/`；打过分的回答留在 `.local/`，不进仓库。
